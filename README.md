# MediBrief

**体調メモを、診察で伝えやすい形に整理するWebアプリ。**

「なんとなく体調が悪い」を自由に書くと、病院・クリニックで医師に伝えやすい7項目の受診メモに整理します。
整理結果はその場で編集でき、医師に見せる・コピーする・印刷（PDF保存）する・この端末に保存しておく、といった使い方ができます。

> **診断ではありません。** 強い症状や不安がある場合は医療機関へ相談してください。
> このアプリは病名・薬・緊急度の判断を一切しません。受診**前**のメモ整理ツールです。

---

## 目的

診察は時間が限られていて、緊張すると伝えたいことを忘れがちです。
MediBrief は「何を、どの順番で伝えるか」を先に整理しておくことで、

- 伝え忘れを減らす
- 症状の経過（いつから・どう変わったか）を言葉にしておく
- 医師に聞きたいことを、質問の形で用意しておく

ことを助けます。整理するだけなので、医学的な判断はユーザーと医師に委ねます。

## 対象ユースケース

- 受診の前に、待合室やベッドの中でスマホから内容をまとめたい
- うまく言葉にできないので、画面を医師に見せて説明の助けにしたい
- 家族の受診に付き添い、本人の言葉を整理して持って行きたい
- 通院ごとのメモを、この端末に残して次回に見返したい

**このアプリが対象にしないこと**：診断、電子カルテ、症状チェッカー、トリアージ、医療者向けの記録。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 自由記述 → 7項目への整理 | 話し言葉のまま書いた内容を、診察で伝えやすい7つの項目に振り分けます |
| AI整理 / ローカル整理 | 画面上で選べます。AIが失敗しても自動でローカル整理に切り替わります |
| 結果の編集 | 各項目の行を書き換え・追加・削除・並び替えできます（下書きとして扱います） |
| 不足情報チェック | まだ書かれていない項目を挙げ、その場で書き足して整理し直せます |
| 症状経過タイムライン | 入力に書かれた時期の表現だけを、書かれた順に並べます |
| 音声入力 | 対応ブラウザでは、話した内容を入力欄に追加できます |
| ローカル履歴 | 作成した受診メモをこの端末のブラウザに保存し、あとから開けます |
| 医師に見せるモード | 操作ボタンを消し、大きな文字で内容だけを表示します |
| コピー / 印刷・PDF保存 | 編集後の内容とタイムラインがそのまま反映されます |

## 画面の流れ（STEP 1〜4）

1ページのまま、いま自分がどこにいるかが分かるようになっています。

```
STEP 1  体調・困っていることを入力（キーボード／音声／入力例）
STEP 2  整理のしかたを選ぶ（AIで整理 / この端末で整理）→ 受診メモを作る
STEP 3  受診メモを確認・編集（不足情報の書き足し → 整理し直しもここから）
STEP 4  受診で使う（医師に見せる / コピー / 印刷・PDF / この端末に保存）
```

### 整理される7項目

| 項目 | 入るもの |
| --- | --- |
| 主な困りごと | いちばん困っている症状（「喉が痛くて」→「のどの痛み」のように言い換え） |
| いつから | 「昨日の夜から：のどの痛み」のように、時期と症状を組にしたもの |
| 症状の変化 | 強くなった・楽になった・時間帯による差など |
| 関係ありそうなこと | 睡眠・食事・仕事・ストレスなど、思い当たること |
| 服薬・持病・アレルギー | 飲んだ薬（市販薬も）、通院中の病気、アレルギー |
| 医師に聞きたいこと | 書かれた不安をもとに組み立てた、**医師に尋ねる質問文** |
| 伝え忘れ防止メモ | 空欄になっている項目の補い方＋持ち物チェック |

入力から拾えなかった項目は空欄のまま、「何を書き足すと伝わりやすいか」だけを案内します（推測で埋めません）。

## AI整理とローカル整理

整理のしかたは画面で選べます。どちらを選んでも、出てくる受診メモの形は同じです。

| | AIで整理 | この端末で整理 |
| --- | --- | --- |
| 処理する場所 | サーバー経由で外部API（OpenAI） | ブラウザの中だけ |
| 入力の外部送信 | **あり**（整理のために送信） | なし |
| APIキー | 必要（サーバー側のみ） | 不要 |
| 使える条件 | `OPENAI_API_KEY` が設定されているとき | 常に |

- `OPENAI_API_KEY` が設定されていれば「AIで整理」が既定になります。未設定なら選択肢自体が無効になり、ローカル整理だけが使えます。
- AI整理を選んだときも、**APIキーが無い・API呼び出しに失敗した・応答の形が壊れていた**場合は、自動的にルールベース整理へ切り替わります（アプリは止まりません）。
- 実際にどちらで整理されたかは、結果の上にバッジと一文で表示されます（「AI整理」「ローカル整理（AI整理に失敗したため…）」）。

### AIにさせること／させないこと

`app/api/organize/route.ts` の `SYSTEM_PROMPT` で、AIの役割を「整理」だけに限定しています。

**させること**：読みやすい言い換え、7項目への振り分け、時系列の構造化、医師への質問文の組み立て。

**させないこと**：病名・原因の推測、薬やサプリの提案、治療法の提案、緊急度・重症度の判定、診療科の決定、入力に無い事実の補完。

さらにコード側でも次の検証をしています（`lib/organizer/validate.ts`）。

- 知らない項目IDは捨て、7項目の形に必ず整える
- 文字列でない項目・空文字・重複を落とし、長さと件数に上限をかける
- **タイムラインの時期表現が入力に含まれない場合は、その行ごと落とす**（AIが日付を作ることへの対策）

## 症状経過タイムライン

入力に書かれた時期の表現（「3日前から」「昨日の夜」「今朝」）だけを抜き出して並べます。

- 実際の日付・時刻には変換しません
- 入力に無い出来事は足しません
- 並べ替えません（書かれた順のまま。前後関係が不明なものを推測して並べない）
- 抜き出せなければ、タイムライン自体を表示しません

## 保存とプライバシー（local-first）

- **クラウドDBは使いません。** サーバーに体調の情報を保存しません（保存先は `localStorage` だけ）。
- 保存されるのは、作成日時・元の入力・編集後の受診メモ・タイムライン・整理方式（provider）です。
- 保存は最大20件。古いものから消えます。1件削除・全件削除ができ、どちらも確認をはさみます。
- 壊れた保存データは読み捨てます（アプリは落ちません）。プライベートブラウズなど保存できない環境では、その旨を画面に出します。
- ローカル整理を選んでいる間、入力内容は外部に送信されません。AI整理を選んだときだけ送信されます。この説明は画面のフッターにも常に出しています。

## 使い方

```bash
npm install
npm run dev
# http://localhost:3000 を開く
```

APIキーの設定は不要です。既定では入力内容はブラウザの中だけで処理され、外部に送信されません。

AI整理も試す場合：

```bash
cp .env.example .env.local
# .env.local に OPENAI_API_KEY=sk-... を書く
```

### 環境変数

| 変数 | 必須 | 説明 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 任意 | 設定するとAI整理が使えるようになります。**サーバー側でのみ読み込み、クライアントには渡しません** |

| `NEXT_PUBLIC_MEMO_PROVIDER` | 任意 | 画面を開いたときの既定。`rule`＝端末内整理から始める／`api`＝AI整理から始める |

### 整理ロジックの仕組み（ルールベース）

1. 入力を句読点で短い文に分ける
2. 薬の名前（「痛み止め」など）を伏せてから、症状の言葉を探して言い換える
3. 時期の表現（「昨日の夜から」「3日前から」）を正規表現で抜き出し、同じ文の症状と組にする
4. 残りの文を手がかり語で振り分ける（質問 → 服薬 → 変化 → 状況 の優先順）
5. どこにも入らなかった文も必ずどこかに残す（入力を捨てない）
6. 空欄の項目から「伝え忘れ防止メモ」を作る

否定表現も見ています。「吐いてはいない」は症状として拾わず、そのままの言葉で残します。

### 整理ロジックを足す

`MemoOrganizer` インターフェース（`lib/types.ts`）に合わせて実装し、`lib/organizer/index.ts` の `ORGANIZERS` に足すだけです。画面側の変更は不要です。
別のAIサービスに変える場合は `app/api/organize/route.ts` の `callOpenAI()` だけ差し替えてください。

## 入力の上限とエラー時の動き

| 状況 | 動き |
| --- | --- |
| 空・空白のみの入力 | 作成ボタンを押せない |
| 2000文字を超える入力 | 入力欄で止まる（文字数を画面に表示）。APIも413で拒否 |
| API呼び出しの失敗・タイムアウト・JSON不正 | ルールベース整理に切り替え、どちらで整理したかを表示 |
| コピーの失敗 | 「長押しで選択してください」という案内に切り替え |
| 音声入力の非対応・マイク拒否 | ボタンを出さない／理由を案内し、キーボード入力を続けられる |
| localStorage が使えない・容量超過 | 保存できなかったことを画面で伝える（アプリは動き続ける） |
| 保存データが壊れている | その項目だけ読み捨てる |

## 注意事項・制約

- **これは医療診断AIではありません。** 病名の断定、薬の提案、緊急度の判定、治療アドバイス、診療科の決定は行いません。
- 整理結果はあくまで下書きです。事実と違うところは編集して使ってください。
- ルールベースなので、言い方によっては項目の振り分けを間違えることがあります（誤って項目が変わっても、入力した文自体は必ずどこかに残ります）。
- 強い痛み、息苦しさ、意識の異常など、心配な症状があるときはメモを作るより先に医療機関へ相談してください。
- 保存はこの端末のブラウザの中だけです。端末をまたいだ同期はしません。共用端末では使い終わったら履歴を削除してください。
- 医療機関で使う場合も、診療記録の正式な代わりにはなりません。
- 音声入力はブラウザの音声認識を使うため、対応状況と認識精度はブラウザ・OSに依存します（Safari/Chromeでは音声がブラウザベンダーのサーバーで処理される場合があります）。
